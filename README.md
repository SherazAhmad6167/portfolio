# Sheraz Ahmad · Portfolio

Personal portfolio built with Next.js 16 (static export), Tailwind CSS 4, GSAP, Motion and Lenis.

## Run locally

```bash
npm install
npm run dev
```

Open http://localhost:3000.

## Edit content

| What | Where |
| --- | --- |
| Name, email, links, stats, stack, experience | `src/content/site.ts` |
| Projects and case studies | `src/content/projects.ts` |
| Screenshots | `raw-screens/` → run `npm run media` |
| Avatar ("SA" liquid-glass monogram) | `src/components/Avatar.tsx` + `.glass-mono` in `src/app/globals.css`; `npm run avatar` renders the PNG copies (phone icon, share image) |
| Globe clients (hero) | `markers` in `src/components/home/Hero.tsx` |
| Globe land dots | generated by `npm run globe` into `src/content/globe-land.json` |

### Adding screenshots

1. Drop the original image in `raw-screens/<project>/`.
2. Add it to the `media` list in `scripts/optimize-media.mjs`. If it shows private data (names, phone numbers, IPs, money), add `blur` boxes in source pixels: `[x1, y1, x2, y2]`.
3. Run `npm run media`. Blurred WebP copies land in `public/media/`.
4. Reference it from a project in `src/content/projects.ts`, e.g. `{ project: "ranjha", name: "dashboard", frame: "browser" }`.

`raw-screens/` is git-ignored on purpose: the originals contain real customer data. Only the blurred copies are published.

## Contact form

Messages are saved to Firestore in the `muhammadsherazahmad` Firebase project (`src/lib/firebase.ts`). Read them in the Firebase console under Firestore → `messages`. `firestore.rules` only lets visitors add new messages; deploy rule changes with `firebase deploy --only firestore:rules`.

If saving fails, the form shows the email address instead. To use Formspree instead of Firestore, set `NEXT_PUBLIC_FORMSPREE_ID=yourFormId` in `.env.local`.

## Deploy

`npm run build` writes a fully static site to `out/`.

### Live site: Firebase Hosting

The site is live at https://muhammadsherazahmad.web.app (project `muhammadsherazahmad`, set in `.firebaserc`).

```bash
npm run build
firebase deploy --only hosting
```

Pages and their data are sent with `Cache-Control: no-cache`, so a new deploy shows up on the next visit; images and code are cached (see `firebase.json`).

### Optional: GitHub Pages

`.github/workflows/deploy.yml` can publish the same build to GitHub Pages. It only runs when started by hand from the Actions tab (repo Settings → Pages → Source: **GitHub Actions** first). Name the repository `SherazAhmad6167.github.io` for the root URL; any other name is served from `/<repo-name>/` and the workflow sets the base path automatically.
